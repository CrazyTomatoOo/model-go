# 登录页流程草图（原型，供确认）

> 关联：wayfinder 票 #5（#1 地图）。已并入 #3/#4 决议：Bearer Token、double-submit cookie CSRF、强制首登改密、统一 401/423。

## 页面清单（v1 共 3 页）

| 页面 | 路由 | 说明 |
|---|---|---|
| 登录页 | `/login` | 用户名 + 密码 |
| 修改密码页 | `/change-password` | 首登强制，改完才能进控制台 |
| 控制台外壳 | `/` | v1 仅占位：顶栏（显示 displayName + 登出） |

## 1. 登录页 `/login`

```
+--------------------------------------------------+
|                                                  |
|                [ model-go 控制台 ]                |
|                                                  |
|   用户名  [__________________________]            |
|   密  码  [__________________________]            |
|                                                  |
|              [ 登  录 ]                           |
|                                                  |
|   （报错区，居中于按钮下方，红字一行）              |
+--------------------------------------------------+
```

- 字段：username（必填）、password（必填，输入框 type=password）。
- 提交：`POST /api/v1/auth/login`，成功响应 `{token, mustChangePassword}`。
  - `mustChangePassword=true` → 跳 `/change-password`。
  - 否则 → 跳 `/`。
- 报错区文案（与 #4 决议一致）：
  - 401：`用户名或密码错误`（用户不存在/密码错同一文案）
  - 423：`登录失败次数过多，账号已锁定，请 15 分钟后再试`
  - 前端校验空字段时本地提示，不打接口。
- 登录成功后：token 存 `localStorage`；同时服务端在登录响应中种下 csrf cookie（double-submit，见 #4），前端读 cookie 值备用。

## 2. 修改密码页 `/change-password`

```
+--------------------------------------------------+
|                首次登录，请修改密码                 |
|                                                  |
|   初始密码    [__________________________]        |
|   新密码      [__________________________]        |
|               至少 12 位                          |
|   确认新密码  [__________________________]        |
|                                                  |
|              [ 确认修改 ]                         |
+--------------------------------------------------+
```

- 字段：oldPassword（初始密码）、newPassword（≥12 位，不限组合，#3 决议）、confirm（前端比对两次输入一致才提交）。
- 提交：`POST /api/v1/auth/change-password`；成功 → 跳 `/`。
- 仅 `mustChangePassword=true` 时可到达；已改密用户访问此路由直接重定向到 `/`。
- 守卫：全局路由守卫检查 `/me` 的 `mustChangePassword`，true 时一切非本页路由强制跳 `/change-password`（防绕过后端之外的前端直达）。

## 3. 控制台外壳 `/`（v1 占位）

```
+---------------------------------------------------------------+
| model-go   训练任务  推理服务  集群        [displayName ▼]     |
+---------------------------------------------------------------+
|                                                               |
|          （v1 占位：登录成功，工作台待后续迭代）                |
|                                                               |
+---------------------------------------------------------------+
```

- 顶栏右侧用户菜单：`退出登录` → `POST /api/v1/auth/logout`（服务端删 Redis 会话）→ 清 localStorage → 跳 `/login`。
- 全局 401 处理（任意接口返回 401）：清 token → 跳 `/login`；423 按登录页同款文案 toast。

## 全局约定（前端）

1. 请求封装：每个请求自动带 `Authorization: Bearer <token>`；写请求（POST/PUT/DELETE）额外带 `X-CSRF-Token: <csrf cookie 值>`（#4 double-submit 决议）。
2. CORS：apiserver 白名单只放行 console 部署源。
3. 三个页面都用 Ant Design 组件（Form/Input/Button/Layout），无自定义视觉设计，v1 用 AntD 默认主题。
